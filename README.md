> Современный тренажёр немецкого языка для русскоязычных — от первых слов до уверенной грамматики.

Deutsch Trainer помогает заниматься короткими сессиями каждый день: тренировать лексику, запоминать артикли, отрабатывать формы глаголов и закреплять результат интервальными повторениями.

## Возможности

### Для ученика

- **Числительные** — немецкие числа с поддержкой вариантов написания.
- **Слова** — карточки «немецкий → русский» и «русский → немецкий», подсказки и категории.
- **Артикли** — тренировка `der / die / das` с цветовой подсветкой.
- **Глаголы** — Präsens, Präteritum, Partizip II и основные формы спряжения.
- **Время** — чтение часов по-немецки, цифровой и аналоговый режимы.
- **Описание картинок** — письменный или голосовой ответ с проверкой.
- **SRS по Лейтнеру** — повторение карточек в нужный момент, пять ящиков и режим «только к повторению».
- **Озвучка** — прослушивание немецких слов и фраз.
- **PWA** — установка на телефон или компьютер и работа с кэшем словаря.
- **Синхронизация** — перенос SRS-прогресса между устройствами по ключу.
- **Тёмная и светлая темы**, адаптивная навигация и удобный мобильный интерфейс.

### Для администратора

- управление словами, категориями и изображениями;
- массовый импорт и экспорт словаря;
- поиск и объединение дубликатов;
- настройка весов ящиков SRS;
- статистика посещений и ответов;
- управление озвучкой и кэшем аудио;
- настройка ИИ-профилей для картинок и проверки ответов.

## Быстрый старт

Требования: **Node.js 22** и **npm 10+**.

```bash
# Установить зависимости
npm install
(cd frontend && npm install)
(cd backend && npm install && npx prisma generate)

# Запустить приложение в режиме разработки
npm run dev
```

После запуска откройте [http://localhost:3000](http://localhost:3000). Корневой сервер одновременно поднимает Express API и Vite.

При первом запуске создаётся SQLite-база `dev.db` и добавляются стартовые слова. Админка находится во вкладке **«Админка»**. Для локальной разработки используется пароль `admin`, если `ADMIN_PASSWORD` не задан.

## Переменные окружения

Пример настроек находится в [`.env.example`](./.env.example). Приложение не загружает `.env` автоматически — передавайте переменные через окружение, Docker или `node --env-file`.

Для production обязательно задайте:

```bash
export ADMIN_PASSWORD='надёжный-пароль'
export JWT_SECRET='длинная-случайная-строка'
```

Основные параметры:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ADMIN_PASSWORD` | пароль админки | `admin` только для разработки |
| `JWT_SECRET` | секрет JWT-cookie | производный от пароля |
| `DATABASE_URL` | путь к SQLite | `file:./dev.db` |
| `PORT` | порт отдельного backend | `3001` |
| `ALLOWED_ORIGINS` | дополнительные Origin для CSRF | — |
| `STATS_TIMEZONE` | часовой пояс статистики | часовой пояс сервера |
| `PIPER_URL` | адрес сервиса Piper TTS | `http://piper-tts:5000` |

Полный список параметров — в [`.env.example`](./.env.example).

## Архитектура

```text
.
├── server.ts                 # единый dev/prod-сервер
├── frontend/                 # React 18 + TypeScript + Vite
│   ├── public/                # PWA, favicon и иконки
│   └── src/
│       ├── components/        # тренажёры, админка и UI-компоненты
│       ├── hooks/             # словарь, SRS, настройки и состояние UI
│       ├── api/               # единый слой запросов к API
│       └── utils/             # карточки, проверка ответов, SRS и импорт
├── backend/                   # Express + Prisma + SQLite
│   ├── prisma/                # схема и seed-данные
│   └── src/                   # API, middleware и сервисы
├── ARCHITECTURE.md            # подробное описание решений
└── .env.example               # пример конфигурации
```

Frontend и backend разделены по пакетам, но в режиме разработки запускаются одной командой через `server.ts`. Для отдельного production-развёртывания предусмотрены Dockerfile в `frontend/` и `backend/`.

## Данные и безопасность

- прогресс ученика по умолчанию хранится локально в браузере;
- админская авторизация работает через HttpOnly-cookie;
- изменяющие запросы защищены проверкой Origin/Referer;
- публичные чувствительные endpoints ограничены rate limit;
- SQLite автоматически использует WAL-режим;
- перед изменением Prisma-схемы рекомендуется сделать резервную копию базы.
